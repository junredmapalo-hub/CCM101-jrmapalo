# Mission Reflection

Working with Docker gave me a clearer understanding of why containers are useful in modern cloud-native environments. Compared with installing an operating system on a Virtual Machine, starting a Docker container is much faster because a container does not need to boot a complete guest operating system. This makes the setup process quicker and usually requires fewer resources. I also learned that port mapping such as `-p 8080:80` is necessary because it connects port 8080 on the host system to port 80 inside the container, allowing the Nginx web server to be reached through the host machine. When `docker rm` is used, the container is removed from the system, including its writable container layer and data that exists only inside that container. This showed me why important data should use persistent storage instead of depending on a container's temporary storage. Containerization also changes how software developers and IT operations teams work together because applications can be packaged with their dependencies and deployed more consistently across different environments. This supports DevOps by making development, testing, deployment, and operations more connected and repeatable. Through this activity, I learned that developers can build applications in a consistent environment while operations teams can deploy and manage the same containers using standardized commands. My GitHub Cloud Computing Portfolio is also evolving because this laboratory adds practical Docker and containerization experience to the research and cloud platform work from previous laboratories. I now have documentation showing how I compared VMs and containers, verified Docker, deployed Nginx, managed a container lifecycle, and documented technical procedures using Markdown. Overall, this mission helped me better understand how containerization supports faster deployment, efficient resource use, and collaboration between development and operations teams.
